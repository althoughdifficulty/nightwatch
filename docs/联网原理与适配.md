# 校园网自动认证 · 原理与适配指南

> 这份文档写给"接手这个项目的人/agent"。
> 目标：**10 分钟内看懂原理，知道该改哪几个参数，以及哪些坑一定会踩。**
>
> 本文所有结论都来自真机实测（约 60 次断网→重连、5 次整夜无人值守运行），
> 不是纸面推演。凡是标「实测」的地方，都是踩过坑之后写下的。

---

## 0. 这个脚本到底在解决什么

**一句话**：在无人值守的清晨，把"电脑没网"变成"电脑有网"，然后交给 BetterGI 去跑游戏日常。

听起来像"点三个按钮"，但真正的难点全在**判断**上：

- 现在到底有没有网？（TCP 通 ≠ 能上网）
- WiFi 到底连上没有？（网卡 Up ≠ 已关联 ≠ 已认证）
- 门户页面到底处在什么状态？（登录表单 / 已登录 / 加载失败 / 验证码）
- 按钮到底点中了没有？（页面会位移，按钮是图片，没有名字）

**每一个判断错了，后面的动作就全是错的**，而且往往"看起来在跑"，实际在空转。

---

## 1. 三个层次：把"没网"拆开看

校园网的"没网"至少有三层，**处理方式完全不同**。先诊断在哪一层，再动手。

### 1.1 物理/驱动层：WiFi 根本没起来

| 状态 | 现象 | 判断方法 |
|---|---|---|
| **无线电关闭**（系统"WLAN"开关） | `netsh wlan show interfaces` **没有 SSID 行** | 网卡 `AdminStatus=Up`，但 `netsh` 报 `0x80342002` |
| **网卡被禁用**（设备管理器/部分设置） | 网卡不可用 | `Get-NetAdapter` 的 `AdminStatus = Disabled` |
| **未关联任何 AP** | 没有 SSID | 有线：`Get-NetConnectionProfile` 为空 |

**关键区分（实测）**：Windows 11 那个"WLAN 开关"关的是**无线电（radio）**，不是网卡。
所以 `Enable-NetAdapter` 对它**无效**——网卡状态一直是 `Up`。必须调 WLAN API 打开无线电（见 §5.1）。

### 1.2 链路层：已关联，但没通过门户认证（captive portal）

这是**最常见**的状态，也是最大的坑：

```
已连上 WiFi（有 IP、有 DNS）
  ↓
但网关不放行外网
  ↓
浏览器打开任何网站 → 被劫持到认证页
```

**最反直觉的一点（实测）**：这种状态下

```
TCP connect 223.5.5.5:53      → 成功 ← 假象！网关接管了连接
TCP connect www.baidu.com:443 → 成功 ← 假象！
HTTPS 请求 baidu              → 超时 / TLS 证书不可信
HTTP  请求某个探测地址         → 可能返回 200（网关代理回的真实内容）
```

**结论：任何"只看 TCP 能不能连"或"只看 HTTP 能不能通"的判断都是错的。**

### 1.3 应用层：认证成功，但外网仍不通

两种情况：

1. **会话失效**：门户页显示"已登录"，但网关那边已经踢掉了（换 IP、超时、设备数超限）。
   → 必须**先断开再重新登录**（本项目的实现：检测到"已登录但外网不通"就点「断开连接」）。
2. **认证延迟**：门户记录登录成功，但网关放行有延迟（**实测最长 65 秒**）。
   → 验收窗口要给够（本项目用 90 秒），否则会误判失败。

## 2. 怎么判断"真能上网"（核心）

### 2.1 唯一可靠的判据

```powershell
# 用系统自带 curl，HTTPS，看是否拿到真实响应
curl.exe -s -o NUL -w '%{http_code}' --max-time 8 https://www.baidu.com
# 返回 1xx~5xx = 通；返回 000 = 不通
```

再串一个备用目标（`https://www.qq.com`），任一成功即算通。

### 2.2 三条禁令（每条都踩过）

| ❌ 不要这样做 | 为什么 |
|---|---|
| **只测 TCP** | 劫持式认证下 TCP 握手必然成功，永远判成"有网" |
| **用 HTTP 兜底** | 有的网关放行 HTTP、劫持 HTTPS；HTTP 200 不代表浏览器/游戏能用 |
| **用 `Invoke-WebRequest`** | 在**某些机器上**它会卡死 8 秒后超时（.NET 栈先试 IPv6 挂住），同一时刻 `curl` 0.4 秒就 200。强设 TLS1.2 也没救 |

### 2.3 还有两个"看起来能用"的探测地址，别用

- `www.msftconnecttest.com`：Windows 自己用来判断联网的地址。
  在实测环境中 **HTTPS 证书链校验失败**（返回 TLS 错误），而 curl 对它也拿不到 200。
  用它当判据 → 明明有网却报"不通"。
- `223.5.5.5:53` / `8.8.8.8`：TCP 可达，但同样会被网关接管，不能作数。

## 3. 认证流程：一个通用模型

绝大多数高校/酒店 captive portal 都长这样：

```
页面: 账号输入框 + 密码输入框
     (+ 运营商单选框：联通/移动/电信)
     (+ 记住密码 checkbox)
     + 登录按钮（通常是 <input type="image">，即"图片"，不是文字按钮）
     + 有时出现验证码
```

本项目的处理顺序（每一步都有原因）：

```
1. 连 WiFi（见 §5）
2. 打开/复用浏览器标签，指向门户 URL
3. 最大化窗口 + 校验尺寸（见 §4.3）
4. 校验地址栏：是不是真的到了门户页（防"停在 about:blank"）
5. 识别页面状态：登录表单 / 已登录 / 未知
6. 若"已登录但外网不通" → 点「断开连接」→ 重新导航 → 回到 5
7. 检查账号密码是否已自动填充（不自己存密码，见 §6）
8. 检查验证码（有就刷新重试，仍无则放弃并截图）
9. 按 ESC 关掉浏览器的"保存密码"下拉（见 §4.4）
10. 点运营商单选框 → 回读确认已选中
11. 点登录按钮
12. 轮询等待"确认/推广"弹窗，出现才点
13. 用 curl 验收（90 秒窗口）
14. 成功后关闭浏览器
```

## 4. UI 自动化：为什么不能用坐标，以及具体怎么做

### 4.1 固定比例坐标为什么必须放弃（实测）

早期版本用"窗口比例 + 基准截图"算点击点：

```
x = 窗口左边 + 窗口宽 × 0.6199
y = 窗口上边 + 窗口高 × 0.4866
```

实测结果：**窗口尺寸没变（2584×1624，最大化校验通过），但页面内容整体下移了约 180px**，
按比例算出的点全部落空，点进了"账号"输入框，于是连续 5 轮认证失败。

另一次实测：同一份脚本，元素真实坐标是 `(1289,1062)`，而比例算出的是 `(1590,778)`
——**横向差 301px，纵向差 284px**。

**结论：坐标只适合做兜底，主路径必须用"元素定位"。**

### 4.2 用 UI Automation 读控件真实矩形

```powershell
$root = [System.Windows.Automation.AutomationElement]::FromHandle($hwnd)
$all  = $root.FindAll([System.Windows.Automation.TreeScope]::Descendants,
                      [System.Windows.Automation.Condition]::TrueCondition)
foreach ($e in $all) {
    $c = $e.Current
    $r = $c.BoundingRectangle     # 物理像素，与屏幕坐标一致（进程需 DPI-aware）
    # $c.ControlType.ProgrammaticName → ControlType.Edit / RadioButton / Hyperlink / Image
    # $c.Name → 控件名字（可能为空，可能带空格）
}
```

**三个必踩的坑（实测）**：

| 坑 | 表现 | 解法 |
|---|---|---|
| **`IsOffscreen` 不可信** | 明明看得见的单选框，UIA 报 `IsOffscreen=True`，被过滤掉 → "找不到元素" | **不要用 IsOffscreen 过滤**，只用"矩形有效（宽高 > 0）"判断 |
| **名字里有空格** | `联   通`（中间 3 个空格） | 用正则 `联\s*通`，别用相等比较 |
| **图片按钮没有名字** | 登录按钮是 `<input type=image>`，UIA 里是 `Hyperlink`/`Image`，`Name=''` | 用几何特征找：在表单区指定 Y 之下、尺寸最大的那个（实测 230×65） |

**取坐标前必须设 DPI 感知**，否则 UIA 的矩形是逻辑像素，和 `SetCursorPos` 不一致：

```csharp
SetProcessDpiAwarenessContext(-4)   // PER_MONITOR_AWARE_V2
// 或旧接口 SetProcessDPIAware()
```

### 4.3 为什么必须先最大化 + 校验尺寸

- 页面是**固定宽度布局**，窗口宽度变了内容不会等比例缩放；
- 所以比例兜底路径只有在"最大化"时才勉强成立；
- 本项目加了一道硬校验：**窗口宽度 ≥ 屏幕宽度 95%**，不够就再最大化 2 次，
  仍不够则 `exit 8` **拒绝点击**（宁可不点，不能点错）。

### 4.4 浏览器的"保存的密码"下拉会盖住控件（实测）

点进账号框后 Edge 会弹出已保存账号列表，**盖住单选框右半边和登录按钮右半边**。

处理：

1. 点击前按 **ESC ×2**（关下拉）；
2. 单选框点**左缘 +12px（圆圈本身）**，不点正中；
3. 登录按钮同样点**左侧 +20px**。

### 4.5 点完要回读确认

```powershell
$sel = $radio.GetCurrentPattern(
    [System.Windows.Automation.SelectionItemPattern]::Pattern).Current.IsSelected
```

没选中就改点中心重试。**"点了"不等于"点中了"**——这是无人值守场景里最容易自欺的地方。

## 5. WiFi 层：三个具体操作

### 5.1 打开无线电（系统 WLAN 开关）

```csharp
WlanOpenHandle(2, NULL, &ver, &handle);
// 关键：pData 传 12 字节的 WLAN_PHY_RADIO_STATE，不是 772 字节的 WLAN_RADIO_STATE
//   { DWORD dwPhyIndex=0; DWORD soft=1(ON); DWORD hard=1(ON) }
WlanSetInterface(handle, &guid, 4 /* wlan_intf_opcode_radio_state */, 12, p, NULL);
```

**实测**：传 772 字节 → 返回 `0x57`（参数错误）；传 12 字节 → 返回 `0`，无线电立刻打开。

> 备用/兜底：`Disable-NetAdapter` + `Enable-NetAdapter` 重启网卡。
> 但实测**它并不能恢复被"WLAN 开关"关掉的无线电**（重启后仍需 WLAN API）。

### 5.2 连接指定 SSID

```powershell
Enable-NetAdapter -Name $adapter            # 仅当 AdminStatus=Disabled
netsh wlan connect name="<你的SSID>"        # 需要系统里已有该网络配置文件（连过一次即可）
```

连接请求可能立即返回"成功"但实际没关联，所以要**轮询 SSID**（最多 90 秒），
并且**每 20 秒重发一次** `netsh wlan connect`（实测重启网卡后无线电恢复需要 30~60 秒）。

### 5.3 读当前 SSID（有两个坑）

| 做法 | 结果 |
|---|---|
| `(Get-NetConnectionProfile).Name` | ❌ 返回的是**连接配置文件名**（可能叫 `你的SSID 2`、`你的SSID 3`），不是 SSID → 会误判"没连上" |
| `netsh wlan show interfaces` 解析 `SSID` 行 | ✅ 正确，但**输出编码是 UTF-8**，而 PowerShell 5.1 默认按 GBK 解码 → 中文全乱码 |

正确写法：

```powershell
$oldEnc = [Console]::OutputEncoding
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$out = & netsh wlan show interfaces 2>&1
[Console]::OutputEncoding = $oldEnc
# 然后正则 ^\s*SSID\s*:\s*(.+)$
```

## 6. 密码从哪来

**本项目不保存任何账号密码。**

它依赖浏览器自己的"记住密码"：

- 门户页要有勾选「记住密码」；
- Edge 已保存该站点的账号密码；
- 脚本只做"检查输入框是否已有值"：

```
输入框值长度 > 0  → 认为已填充
全部为空         → exit 4，提示人工登录一次
```

**判断"是否填充"时务必排除浏览器自己的输入框**（地址栏 `地址和搜索栏`、`搜索框`），
否则地址栏永远非空，"账号密码是空的"这道检查就永远不触发（实测踩过）。

## 7. 与 BetterGI 的衔接

| 事实 | 影响 |
|---|---|
| BetterGI 是**单实例** | 已有进程时不要再启动，直接复用/唤出窗口 |
| BetterGI 通常以**管理员**运行 | 自动化脚本也必须以管理员运行，否则 UIA 读不到它的控件（子元素数为 0） |
| 它会自己启动游戏 | 脚本只需要点它的"一条龙播放键" |
| 播放键位置 | 在 `任务列表` 文本右侧、最左边的那个 Button（实测名称空、67×49） |
| 页面切换 | 点"一条龙"导航后，要等 `任务列表` 出现，再找播放键 |
| 连续点击会被识别成"停止" | 一次流程只点一次播放键；靠日志校验是否真的启动 |

**点击前必须校验遮挡**：`WindowFromPoint` 命中的顶层窗口是不是 BetterGI。
如果是别的窗口（比如用户正在用的浏览器），**重新置前台并重试 3 次**，仍不行就放弃——
直接点下去会点到别人的窗口上。

## 8. 时序与可靠性（无人值守必须处理）

| 场景 | 处理 |
|---|---|
| **定时唤醒后屏幕是黑的** | 唤醒定时器只叫醒系统，显示器常保持关闭。要主动开屏：广播 `SC_MONITORPOWER -1` + **真实鼠标输入**（`mouse_event` 相对移动），并用 `SetThreadExecutionState(ES_DISPLAY_REQUIRED)` 保持 |
| **鼠标移动不算"用户输入"** | `SetCursorPos` 只是挪指针，不重置输入空闲计时器 → 屏幕亮了又灭。必须 `mouse_event` |
| **睡眠前开着开始菜单** | 唤醒后开始菜单原样留在桌面上，盖住所有窗口。启动时先按 **ESC ×2** 并记录前台窗口类名 |
| **唤醒后 GPU 没就绪** | 立刻拉起游戏可能触发显卡超时（蓝屏 `0x116`）。本项目把"认证完成 → 启动游戏"的间隔设为 **90 秒** |
| **错过时间后补跑** | `StartWhenAvailable` 会在你早上用电脑时突然启动 → 加"迟到保护"：超过预定时间 120 分钟就放弃 |
| **电池供电** | 任务层 `DisallowStartIfOnBatteries`，脚本层再查一次电源，双重保护 |
| **认证失败** | 重试 5 轮（每轮间隔 60 秒），全败则 **不启动游戏**（`exit 12`）——没网跑游戏只会产生几十分钟的无效操作 |

## 9. 适配你自己的环境（checklist）

### 9.1 必改的两个参数

```powershell
-PortalUrl  "http://<门户主机>:<端口>/<门户路径>/login.jsp"
-WifiSsid   "<你的WiFi名称>"
```

装任务时：

```powershell
.\Install-BetterGI-OneDragon-Task.ps1 -Time 06:00 `
    -PortalUrl "http://10.0.0.1:8080/portal/login.jsp" -WifiSsid "CampusWiFi"
```

### 9.2 可能要改的地方（按概率排序）

| 位置 | 什么时候要改 | 怎么改 |
|---|---|---|
| 运营商单选框的名字正则 | 你的门户不叫「联通/移动」 | 抓一次 UIA（§9.3），把 `联\s*通` 换成实际名字 |
| 登录按钮的筛选条件 | 登录按钮不是"表单区最大的 Hyperlink/Image" | 改 `Find-LoginButtonRect` 的尺寸/Y 范围 |
| 验证码判定 | 你的门户验证码没有"验证码"文字 | 换成检测 `<img>` 或输入框数量 |
| 比例兜底坐标 `$RATIO` | 只是兜底，通常不用动 | 用 `-DryRun` 校准 |
| 页面状态特征词 | 已登录页没有「断开连接/当前登录账号」等文字 | 改 `Get-PageState` 里的正则 |

### 9.3 怎么抓自己门户的 UIA 结构

用仓库里的 `tools/Dump-PageUia.ps1`（不需要管理员，只要能把浏览器打开）：

```powershell
.\tools\Dump-PageUia.ps1 -Url "http://<你的门户>/login.jsp" -OutFile ".\portal-uia.txt"
```

它会输出每个控件的 `类型 / 名字 / 矩形`，形如：

```
Edit        y=568 x=1575 w=403 h=53  name=''
RadioButton y=761 x=1575 w=106 h=49  name='联   通'
Hyperlink   y=880 x=1575 w=230 h=65  name=''
```

拿到这份结构，改 §9.2 里的几处就很快了。

### 9.4 验证顺序（别跳步）

```powershell
# 1. 只看状态，什么都不点
.\Test-NetworkAuth.ps1 -Mode status

# 2. 强制跑，但只算坐标不点击（会把点画在截图上）
.\Test-NetworkAuth.ps1 -Mode dry

# 3. 真正跑一次认证（会断网/联网，人在旁边看着）
.\Test-NetworkAuth.ps1 -Mode force

# 4. 完整演练：先登出，再自动认证回来
.\Test-NetworkAuth.ps1 -Mode rehearsal

# 5. 最后才是定时任务整夜无人值守
```

## 10. 排错速查

| 症状 | 最可能的原因 | 处理 |
|---|---|---|
| 日志说「网络已连通」但实际没网 | 用了 TCP/HTTP 判断 | 改成 curl + HTTPS（§2.1） |
| 明明有网却报「不通」 | 探测地址选错（如 msftconnecttest）或客户端卡死 | 换 baidu/qq + curl |
| 点「联通」没反应 | 坐标偏了 / 被下拉遮挡 / 页面结构变了 | 改元素定位 + ESC + 点左缘 |
| 页面状态 unknown | 浏览器停在 about:blank 或错误页 | 校验地址栏并主动导航；失败时重试一次 |
| 一直等到超时 | 无线电/网卡没起来 | 先开无线电（§5.1），40 秒无 SSID 就提前交给认证脚本 |
| 认证成功后游戏仍登录失败 | 网关放行有延迟 / 会话被踢 | 验收窗口给到 90 秒；"已登录但不同"时先断开再登 |
| 屏幕一直是黑的 | 只用了 SetCursorPos | 改用 mouse_event + ESC 清浮层（§8） |
| 早上起来发现它在跑 | StartWhenAvailable 补跑 | 加迟到保护 |
| 游戏启动后蓝屏 `0x116` | 显卡驱动超时 | 加大启动延迟；更新驱动；必要时关 PCIe ASPM |

## 11. 这套方案的边界

- **它不破解任何认证**：只是把鼠标点在认证页该点的地方，账号密码由浏览器保存。
- **它依赖页面结构与文案**：门户改版、BetterGI 改版都可能导致失效，需要按 §9.2 调整。
- **它无法应对需要人机交互的场景**：验证码、短信验证、二次确认页——遇到就截图并退出，
  留给人工。
